1 Какво е ClawBox?

ClawBox е десктоп програма за управление на електронни компоненти. Представи си го като електронен бележник, в който записваш:

  • Какви компоненти имаш (Nvidia Jetson, хард диск...)
  • Кой ти ги доставя (AliExpress, Mouser...)
  • В какви категории попадат
  • Кои са твоите клиенти
  • Какви поръчки са направени
Аналогия
Представи си магазин за части. Имаш рафтове с компоненти (КОМПОНЕНТИ), етикети на рафтовете (КАТЕГОРИИ), списък с доставчици (ДОСТАВЧИЦИ), картотека с клиенти (КЛИЕНТИ) и тетрадка с поръчки (ПОРЪЧКИ). ClawBox е цялото това нещо, но на компютъра.

2 Файлова структура

Проектът има 4 Java файла, 2 скрипта и 1 драйвер:

ClawBoxProject/ src/ папка с код MainClass.java Входна точка — стартира програмата ClawBoxFrame.java Главен прозорец — цялата визия + логика MyDBConnection.java Връзка с базата данни MyModel.java Модел за таблиците (показва данни) driver/ h2-2.2.224.jar H2 база данни (вграден двигател) build.bat Скрипт за компилиране (Windows) build.sh Скрипт за компилиране (Linux/Mac) DB/ тук живее базата данни (създава се автоматично) clawbox.mv.db самият файл с данните
Аналогия
MainClass = ключът за запалване на колата
ClawBoxFrame = самата кола (волан, педали, табло)
MyDBConnection = бензиностанция (доставя данни)
MyModel = табло с уреди (показва информацията)
h2-2.2.224.jar = двигателят на базата данни
build.bat = бутонът "START"

3 Как се стартира (build.bat)

Когато натиснеш build.bat, се случват 3 неща:

Стъпка 1: Създай папка DB/
mkdir DB — място за базата данни
↓
Стъпка 2: Компилирай кода
javac превръща .java файлове в .class файлове
↓
Стъпка 3: Стартирай програмата
java MainClass — отваря прозореца
.java файлове = код, който хората четат
.class файлове = код, който компютърът изпълнява
javac = преводач от човешки на машинен език

4 Какво е база данни и как работи H2

Какво е база данни?

Базата данни е като Excel файл — има таблици с редове и колони. Но вместо да отваряш Excel ръчно, програмата чете и пише в нея автоматично.

Какво е H2?

H2 е вградена база данни. Тя не е отделна програма (като MySQL). Тя живее вътре в програмата — в един единствен файл:

DB/clawbox.mv.db — целият ти database е в ТОЗИ файл

Кога се създава?

Първо стартиране
Файлът НЕ съществува → H2 го СЪЗДАВА → вкарва начални данни
↓
Всяко следващо стартиране
Файлът СЪЩЕСТВУВА → H2 го ОТВАРЯ → данните си остават
Аналогия
H2 е като тетрадка. Първия път я купуваш и пишеш първите страници. Следващия път просто я отваряш — написаното си е там. Ако я изгубиш (изтриеш файла), трябва да купиш нова и да започнеш отначало.
Важно: Ако изтриеш DB/clawbox.mv.db, базата се създава отново от нулата. Всички данни, които си добавил, се губят!

6 Връзки между таблиците (Foreign Keys)

Foreign Key (FK) е връзка между две таблици. Вместо да пишеш цялото име на категорията във всеки компонент, записваш само номера (ID) на категорията.

Аналогия
Представи си, че имаш рафт с номер #1 и на него пише "Nvidia Jetson Nano". Когато слагаш компонент на този рафт, не пишеш пак "Nvidia Jetson Nano" — просто пишеш "рафт #1". Това е Foreign Key — указател към друга таблица.

Четирите FK връзки

Таблица Колона (FK) Сочи към Какво означава
KOMPONENTI IDKATEGORIYA KATEGORII.ID Всеки компонент има категория
KOMPONENTI IDDOSTAVCHIK DOSTAVCHICI.ID Всеки компонент има доставчик
PORUCHKI IDKOMPONENT KOMPONENTI.ID Всяка поръчка е за конкретен компонент
PORUCHKI IDKLIENT KLIENTI.ID Всяка поръчка е от конкретен клиент

Визуална схема

KATEGORII
DOSTAVCHICI
↓ FK           ↓ FK
KOMPONENTI
IDKATEGORIYA → KATEGORII.ID  |  IDDOSTAVCHIK → DOSTAVCHICI.ID
↓ FK
PORUCHKI
IDKOMPONENT → KOMPONENTI.ID  |  IDKLIENT → KLIENTI.ID
↑ FK
KLIENTI
Защита: Не можеш да изтриеш категория, ако има компоненти в нея. Не можеш да изтриеш клиент, ако има поръчки за него. Базата данни не позволява да развалиш връзките (Referential Integrity).

Как работи всеки бутон

"Добави" (INSERT)
Чете стойностите от текстовите полета → валидира → изпълнява INSERT INTO таблица VALUES(...) → презарежда таблицата
"Промени" (UPDATE)
Кликваш ред в таблицата → полетата се попълват → промениш каквото искаш → натискаш бутона → UPDATE таблица SET ... WHERE ID=? → презарежда
"Изтрий" (DELETE)
Кликваш ред → натискаш бутона → DELETE FROM таблица WHERE ID=? → презарежда. Ако има FK зависимости — показва грешка!
"Търси" в Справка (SELECT с JOIN)
Избираш филтри от dropdown менютата → SELECT ... FROM KOMPONENTI LEFT JOIN KATEGORII ... WHERE ... → показва резултатите

9 Четирите Java файла — подробно

1. MainClass.java (7 реда)

Най-простият файл. Прави едно-единствено нещо:

import javax.swing.SwingUtilities; public class MainClass { public static void main(String[] args) { SwingUtilities.invokeLater(ClawBoxFrame::new); } // ↑ създава прозореца на правилната нишка }
SwingUtilities.invokeLater — Swing (графичната библиотека) иска всичко да се случва на "Event Dispatch Thread" (EDT). Това гарантира, че прозорецът се създава безопасно. Без него може да има бъгове при зареждане.

2. MyDBConnection.java (84 реда)

Управлява връзката с базата данни. Има 2 метода:

getConnection()

Връща връзка (Connection) към базата данни. Ако вече има отворена — връща същата. Ако няма — създава нова.

initDB()

Създава 5-те таблици (CREATE TABLE IF NOT EXISTS) и вкарва начални данни (3 категории, 3 доставчика) — само ако таблиците са празни.

// Ключов ред — връзка към H2 базата данни conn = DriverManager.getConnection("jdbc:h2:./DB/clawbox", "sa", ""); // ↑ път до файла ↑ потребител ↑ парола (празна)
jdbc:h2:./DB/clawbox — това е "адресът" на базата данни.
jdbc = Java Database Connectivity (стандарт за връзка с бази)
h2 = типът на базата
./DB/clawbox = файлът DB/clawbox.mv.db в текущата папка

3. MyModel.java (47 реда) — предоставен от преподавателя

Мостът между базата данни и таблицата на екрана. Наследява AbstractTableModel.

SQL заявка
SELECT * FROM KOMPONENTI
↓
ResultSet
Java получава резултата от базата
↓
new MyModel(rs)
MyModel прочита всички редове и ги записва в ArrayList
↓
table.setModel(model)
JTable показва данните на екрана

setRS(ResultSet rs)

Чете всички редове от ResultSet и ги записва в ArrayList. Също запомня имената на колоните.

getValueAt(row, col)

JTable вика този метод за всяка клетка — "дай ми стойността на ред X, колона Y".

Аналогия
MyModel е като фотокопие на данните. Вместо JTable да чете директно от базата данни (което е бавно и опасно), MyModel прави "снимка" на данните и JTable гледа снимката.

4. ClawBoxFrame.java (~1200 реда) — основният файл

Това е сърцето на програмата. Съдържа:

Визия (UI)

  • JFrame — главен прозорец
  • JTabbedPane — 6 таба
  • JTextField — текстови полета
  • JComboBox — падащи менюта
  • JButton — бутони
  • JTable + JScrollPane — таблици

Логика (Controller)

  • ActionListener класове за всеки бутон
  • MouseListener за кликване по ред
  • Валидация на входни данни
  • SQL заявки (INSERT, UPDATE, DELETE)
  • refresh методи за презареждане

Важни концепции в ClawBoxFrame

PreparedStatement (вместо Statement)
Вместо да лепим стрингове ("INSERT ... VALUES('" + name + "')"), използваме ? като placeholder:

PreparedStatement ps = conn.prepareStatement("INSERT INTO ... VALUES(?, ?, ?)");
ps.setString(1, name);

Това предпазва от SQL Injection (хакерска атака) и е по-сигурно.
try-with-resources
try (PreparedStatement st = conn.prepareStatement(sql)) { ... }

Java автоматично затваря ресурса (PreparedStatement, ResultSet) след блока. Без това може да "изтечат" ресурси и програмата да забави.
LEFT JOIN
Когато зареждаме Компоненти, искаме да видим имената на категорията и доставчика, а не техните ID номера:

SELECT ... FROM KOMPONENTI LEFT JOIN KATEGORII ON ...

LEFT JOIN означава: "вземи всички компоненти, дори ако нямат категория".
SQLState "23503" — FK грешка
Когато се опиташ да изтриеш категория, която се използва от компонент, базата данни хвърля грешка с код 23503. Ние я хващаме и показваме съобщение: "Не може да се изтрие — има свързани записи!"

10 Обобщение за изпита

Кратък отговор: "Какво прави проектът?"

ClawBox е Java Swing CRUD приложение с вградена H2 база данни, което управлява електронни компоненти — техните категории, доставчици, клиенти и поръчки. Интерфейсът е с 6 таба — 5 за CRUD операции и 1 за справка с филтриране.

Кратък отговор: "Как работи базата данни?"

H2 е вградена (embedded) база данни, която живее в един файл (DB/clawbox.mv.db). При първо стартиране се създават 5 таблици и се вкарват начални данни. При следващо стартиране данните си остават. Връзката се осъществява чрез JDBC с адрес jdbc:h2:./DB/clawbox.

Кратък отговор: "Какви са връзките между таблиците?"

Има 4 Foreign Key връзки: KOMPONENTI сочи към KATEGORII и DOSTAVCHICI (всеки компонент има категория и доставчик). PORUCHKI сочи към KOMPONENTI и KLIENTI (всяка поръчка е за конкретен компонент от конкретен клиент). FK-ите пазят целостта на данните — не можеш да изтриеш запис, който се използва другаде.

Кратък отговор: "Какво е MyModel?"

MyModel наследява AbstractTableModel и служи като мост между ResultSet (данни от базата) и JTable (таблица на екрана). При създаване прочита всички редове от ResultSet в ArrayList и запомня имената на колоните. JTable после вика getValueAt() за всяка клетка.
